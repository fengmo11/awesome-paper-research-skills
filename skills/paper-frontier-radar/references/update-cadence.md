# Update Cadence

Use this reference to decide how often to refresh repository and paper workflow
signals.

## Cadence

| Interval | Tasks |
| --- | --- |
| Daily, when launching | Check GitHub topics, key repos, and recent venue/tool announcements. |
| Weekly | Add new repositories, paper tools, MCP servers, and high-signal skills to the frontier ledger. |
| Monthly | Refresh stars/forks, install instructions, stale links, and "best new tools" sections. |
| Quarterly | Re-evaluate the full workflow, merge or split skills, and update acceptance gates. |

## Backlog Labels

- `adopt-now`: improves a current gate and has clear provenance.
- `watch`: promising but not mature enough.
- `test-locally`: likely useful but needs a runnable check.
- `cite`: useful as a source or precedent.
- `security-review`: inspect before installing or recommending.
- `remove-or-demote`: stale, broken, duplicated, or no longer relevant.

## Minimum Weekly Output

Produce:

1. Five to ten checked sources.
2. One short trend paragraph.
3. A table of accepted changes.
4. A table of watch-only items.
5. Any human-review blockers.
